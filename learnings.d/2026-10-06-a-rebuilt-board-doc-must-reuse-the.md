## 2026-10-06 [report_gen][cc-docs] A rebuilt board doc must reuse the filed document's exact title and project
cc-docs treats a filing as the same document only when the --source path matches, or else the title matches in the same project. A board's docs are rebuilt from a new worktree each time, so the source path rarely matches, and report_gen's generated title ("PCB-0024-A rf-load-50ohm highlight doc") did not match the hand-made one in the library ("PCB-0024-A rf-load-50ohm highlights"). cc-docs minted 002-0048/0049 instead of revisions, and they had to be retired and refiled by hand. report_gen now reads the register read-only ($CC_DOCS_ROOT/register.json, else ~/.cc/documents/register.json), finds the board's document of that kind (source in reports/<kind subdir>/ under the board's directory, or last revision describing the PN), and files under its project number and exact title. It falls back to "<PN> <board> <kind>" in project "Boards" only when none exists. "Boards/<PN> <name>" is refused while project 002 is named "Boards" outside any group: `cc-docs number --project ... --title ...` checks this without filing, because it reserves nothing. Tests must never read the owner's register, so conftest points report_gen.DOCS_HOME at an empty directory and clears CC_DOCS_ROOT.
