## Findings

- Extended-feeder count always 0 on pipeline boards: _assembly_counts built a ref->basic map
  from refs/ref keys, but S6 parts.json is per-DISTINCT-part (basic, no refs) -> empty pmap,
  n_extended=0. pd-trigger: 13 of 24 distinct parts Extended, $39 feeder fees priced $0
  (order_quote.py:120-134 pre-fix; boards/pd-trigger/fab/quote.json; stm32-blinky
  P10-digest.md puzzled over it). 4/4 boards.
- H5 compare apples-to-oranges: estimate = selected row total (PCB+assembly) vs API
  real_price = PCB-only (Open API has no assembly surface). pd-trigger read as 19.65 vs 6.2
  when the PCB estimate was actually 2.00 - 3.1x LOW, direction of error masked
  (order_submit.py:542 pre-fix). 2/2 credentialed runs.
- Created-latch armed only on SUCCESS: ambiguous/failed create (unknown_error) or mid-create
  crash left nothing on disk -> second --api-create proceeded mechanically; a WEB order
  recorded via --order-number did not arm the latch at all (order_submit.py:657-668 pre-fix;
  LEARNINGS.md:1635; ladder rows 138/162 open; lumina-carrier order.json showed the bypass).
- jlc_pricing.yaml headline runs 1.9-3.1x low on PCB price (no copper-weight term, silent
  qty snap); magnitude lived only in SKILL Known limits / LEARNINGS (ladder row 141).
- Bench fixture declared copper_oz: 2.0 that score_p10 never reads (manifest.yaml:309 vs
  bench.py:418-431) - false coverage signal.
- Polling session-bound: pd-trigger jumped Pending Review -> Shipped between polls;
  order_uuid null on both orders so wip/get and tracking-number surfaces never exercised
  live. Acceptable per non-blocking contract; documented unknown, fails null-safe.
